# Testing & CI Policy

## Running tests locally

```sh
nimble test              # run all tests
```

Read the output, not `$?`: nimble 0.22.2 exits 0 even when a task raises, so a failing suite prints `FAILED:` and a traceback and still returns 0. The task ends with `ALL TESTS PASSED (n files)` when everything really passed.

CI does not rely on that exit code — it runs the same files through a shell loop with `set -e` (see `.github/workflows/ci.yml`). Keep the two in step: `t*.nim`, recursively, excluding `tests/compile_fail/`.

## Test layers

| Layer | What it proves | Where |
|---|---|---|
| Layer-0 smoke | the library links, the header parses, a context can be created and destroyed | `tests/t_proj_abi_smoke.nim` |
| Unit | constructors, predicates, accessors, error paths | `tests/t_*.nim` |
| Differential | nimproj's numbers match PROJ's own | `tests/fixtures/` + `tests/tools/gen_fixtures.sh` (from v0.2.0) |
| Edge cases | `Inf`/`NaN` input, invalid CRS strings, `nil` handles, out-of-range coordinates, empty and one-point batches | `tests/test_edge_cases/` |
| Threads | one `ProjContext` per thread, no shared state | from v0.9.0, `--threads:on` |
| Negative compile | code that **must not** compile (e.g. copying a context) | `tests/compile_fail/`, asserted by `nimble test` |

All test files MUST be named `t_*.nim`: `nimble test` walks `tests/`
recursively and skips anything else, silently.

**Every directory that holds `t_*.nim` files needs its own `config.nims`** with
`switch("path", "$projectDir/../src")`. Nim reads config files from the main
file's own directory, not from its ancestors, so `tests/config.nims` covers
`tests/*.nim` and nothing deeper — a nested `tests/test_edge_cases/t_x.nim`
fails with `cannot open file: nimproj/...`. This is the classic "module not
found in tests" that the layout has to pre-empt, so every test directory carries one such file.

## Negative compile checks

Some guarantees are "this must not compile", and those need a different shape: a
file full of code that has to be rejected.

- `tests/compile_fail/*.nim` — `nimble test` runs `nim c` on each and fails the
  build if any of them *succeeds*.
- The directory is skipped by the test-file walker, and its files are
  deliberately **not** named `t_*.nim`, so the walker cannot pick them up.
- **Do not try to test these with `static: assert(not compiles(...))`.** Nim's
  `'=copy' is not available` diagnostic is raised in the destructor-injection
  pass, which neither `compiles()` nor `nim check` reaches — both report success
  for code that does not build. That is why the check needs a full `nim c`. A
  `not compiles(...)` probe passes vacuously for exactly this reason.
- Keep each file short: the assertion is "it failed", so a typo would also pass.
  A four-line file is one you can read and confirm the reason.

## The oracle is PROJ itself

Differential fixtures are generated by calling the **system PROJ CLI**, so the
comparison runs against the very library the binding links. No version skew.

```sh
# proj-string form: no CRS axis order involved, so no ambiguity
echo "12.5 41.9" | cs2cs +proj=longlat +datum=WGS84 \
                        +to +proj=utm +zone=33 +datum=WGS84 -f "%.9f"
# 292624.875254328   4641695.877909009   0.000000000

# the pipeline the same transform is built from, for pipeline tests
projinfo -q -o PROJ EPSG:4326 EPSG:32633
```

Two rules that come from getting this wrong once already:

1. **Do not use `cs2cs EPSG:4326 EPSG:32633` with longitude/latitude input.** It
   reads the CRS's authority axis order, so it silently interprets the first
   number as latitude. That is the whole subject of the axis-order default
   documented in [Context lifecycle](../getting-started/context-lifecycle.md).
2. **pyproj is not the oracle.** Its wheels bundle their own `libproj` — 9.8.1
   against 9.7.1 on the machine this was set up on — so it cannot be used to
   prove *this* library matches *this* PROJ. pyproj is a documentation reference
   for API shape only.

Fixtures record the PROJ release string they were generated with, and CI warns
when the local PROJ's major.minor drifts from it: a user on 9.9 may see a
different chosen operation from a user on 9.7 for datum-boundary CRS pairs.

## Merge gate

A change merges when:

- `nimble test` passes locally
- CI is green for Linux, macOS and Windows, on `stable` and `devel` Nim
- `mkdocs build --strict` passes (docs changes)
- new behaviour that a user can observe has a test that would fail without it

Windows is the least predictable matrix entry — linking is the usual cause.
`devel` failures are reported but do not block.

## What not to test

Wiring, forwarding, and "does the source text say this" assertions. The
differential layer exists so that numeric claims are checked against the engine
rather than against a hand-copied constant.
